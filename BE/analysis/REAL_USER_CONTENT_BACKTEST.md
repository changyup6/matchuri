# 역삼 실사용자 콘텐츠 추천 백테스트

## 결론

업종 카테고리와 가격대를 사용자의 취향으로 간주한 기존 모델은 제거한다. 실제 역삼
리뷰 replay에서 품질순보다 일관되게 낮았다. 새 서버 정책은 다음처럼 제한적으로
변경했다.

1. 베이지안 품질 점수는 항상 유지한다.
2. 음식점은 메뉴에서 계산한 8개 연속축으로 표현한다.
3. 한 사용자의 명시적 `like/dislike`로만 8차원 선호를 갱신한다.
4. 개인화는 5회 이전에는 0, 20회에 최대 10%까지만 연다.
5. 카테고리는 화면 표시와 운영 통계에만 쓰고 추천 점수에는 넣지 않는다.

새 개인화의 우위는 아직 통계적으로 확정되지 않았다. 따라서 이것은 검증된 품질
백본을 보존하면서 실제 앱 스와이프로 다음 증거를 쌓기 위한 guarded policy다.

## 왜 추가 수집했는가

기존 사용자 그래프와 역삼 전수 데이터의 교집합에서는 메뉴·리뷰·사진 벡터를
시험하기에 사용자별 역삼 이력이 부족했다. 메뉴, 표현력 높은 맛 리뷰, 이용경험 리뷰,
이미지, 협업 필터링을 각각 시험했지만 모두 품질 기준선을 유의하게 넘지 못했다.

그래서 역삼 가게 리뷰에서 여러 번 관측된 작성자만 우선해 100명 파일럿을 추가했다.
제품 범위를 넓히지 않고 역삼 리뷰만 보존했다.

- 채택 사용자: 100명
- 시도 사용자: 121명
- 보존한 역삼 리뷰: 2,517건
- API 호출: 543회, 단일 worker
- 제외: 비공개/오류 17명, 월 20건 초과 활동 4명
- 정상 범위: 공개 리뷰 20~1,200건, 월 리뷰 속도 20건 이하

파일럿 27명과 기존 그래프 23명을 합쳐 20회까지 동일 조건으로 평가 가능한 50명을
확보했다. 이 시점에서 표본 최소선 30명을 넘었으므로 추가 크롤링은 중단했다.

## 검증 프로토콜

- 범위: 역삼동 음식점 2,795곳 중 실제 카드 자격(사진 1장 이상, 리뷰 1건 이상)을
  만족하는 2,216곳
- 중복 처리: 사용자-가게별 최신 평가 1건
- 시간 분할: 사용자별 마지막 30%를 고정된 미래 정답으로 사용
- 관측량: 앞 이력의 3, 5, 10, 20건만 각각 사용
- 라벨 대용값: 카카오 별점 4~5는 선호, 1~3은 비선호
- 누수 방지: 평가 사용자 50명의 리뷰 1,600건을 음식점 리뷰 벡터와 품질 계산에서 제거
- 일반화 검증: 사용자 단위 5-fold out-of-fold
- 불확실성: 사용자 단위 10,000회 bootstrap 95% 신뢰구간
- 평가: 사용자별 AUC와 NDCG@5

`방문하지 않은 가게 = 비선호`로 간주하지 않았다. 실제로 방문하고 평가한 미래 가게
중 선호와 비선호의 상대 순위만 측정했다.

## 주요 결과

### 1. 콘텐츠 multi-vector와 카테고리 기준선

| 관측 수 | 품질 | 기존 카테고리·가격 | 학습형 메뉴·맛·경험 혼합 |
|---:|---:|---:|---:|
| 3 | 0.663 | 0.591 | 0.657 |
| 5 | 0.663 | 0.598 | 0.671 |
| 10 | 0.663 | 0.599 | 0.666 |
| 20 | 0.663 | 0.583 | 0.679 |

20회 학습형 혼합은 품질 대비 `+1.6%p`, 95% CI `[-0.7,+3.9]`였다. 가능성은
있지만 0을 포함한다. 반면 기존 카테고리·가격은 20회 `-8.0%p`, 95% CI
`[-13.4,-2.8]`로 명확히 열세다.

### 2. 실패한 대안

| 방법 | 관측 | 결과 |
|---|---|---|
| BGE raw 의미 유사도 | 메뉴·리뷰 문장 의미가 가까운가 | 품질 대비 크게 열세 |
| 선호 metric 학습 | 두 음식점을 같은 방향으로 평가하는가 | 비평가 holdout pair AUC 0.497 |
| 저차원 contextual PCA | 사용자가 좋아하는 BGE 연속축 직접 적합 | 20회 AUC 0.647, 품질보다 낮음 |
| 음식 사진 | 음식/공간 이미지 별도 벡터 | 음식 0.458, 공간 0.508; 혼합 시 가중치 0 선택 |
| 협업+콘텐츠 전이 | MF item factor를 콘텐츠로 cold-start | 품질을 넘지 못함 |

일반 의미 공간은 취향 공간이 아니었다. “메뉴가 비슷하다”와 “같은 사람이 좋아한다”를
동일시하면 안 된다.

### 3. 해석 가능한 메뉴 8축

축은 `맵기, 달콤, 분위기, 푸짐, 술, 건강, 고기, 국물`이다. 메뉴명과 각 축의
긍정/부정 설명을 BGE로 비교하고, 가게별로 축마다 가장 강한 메뉴 3개의 평균을 썼다.

| 관측 수 | 품질 | 실제 배포 스케줄 | 품질 대비 |
|---:|---:|---:|---:|
| 3 | 0.663 | 0.663 | 0.0%p |
| 5 | 0.663 | 0.663 | 0.0%p |
| 10 | 0.663 | 0.669 | +0.5%p, 95% CI 약 `[0.0,+1.3]` |
| 20 | 0.663 | 0.668 | +0.5%p, 95% CI `[-0.4,+1.5]` |

축 단독 AUC는 약 0.50으로 쓰면 안 된다. 품질에 작게 보정할 때만 손상을 막을 수
있었다. 20회에서는 5개 outer fold가 모두 ridge 1,000과 보정 0.10을 선택했다.

## 배포 수식

가게 `i`의 품질과 메뉴축을 각각 `q_i`, `x_i`라 한다. 선호는 `y=+1`, 비선호는
`y=-1`이다.

```text
P_u = 1000 I + Σ x_i x_iᵀ
b_u = Σ y_i x_i
θ_u = P_u⁻¹ b_u

a(n) = 0                         (n < 5)
       0.10 × (n - 5) / 15       (5 ≤ n < 20)
       0.10                      (n ≥ 20)

score(u,i) = q_i
           + a(n) × z(x_iᵀθ_u)
           + exploration(u,i)
           - recent_similarity(u,i)
```

- 10번째마다 posterior uncertainty에 최대 0.05 탐색 보너스를 준다.
- 최근 두 카드와 메뉴축 방향이 겹치면 최대 0.05 감점한다.
- 이미 보여준 카드는 제외한다.
- 업데이트는 8차원이라 요청당 비용이 작고, 로그 replay 결과가 결정적이다.

## 이 구조가 현재 더 나은 이유

- 품질 AUC 0.663이라는 가장 강한 검증 기준선을 버리지 않는다.
- 업종명이 아니라 음식 특성의 연속값을 학습한다.
- 좋아요와 싫어요가 모두 반대 방향으로 모델에 반영된다.
- 축 이름이 있어 관리자 화면에서 왜 바뀌었는지 확인할 수 있다.
- 데이터가 적을 때 개인화가 품질을 덮어쓰지 않는다.
- 메뉴 없는 가게는 모든 축을 중립 0으로 처리한다.

## 아직 증명되지 않은 것

과거 별점은 앱 스와이프와 다르며, 사용자가 어떤 카드를 노출받았는지도 알 수 없다.
따라서 탐색 정책 자체는 historical replay로 인과 검증할 수 없다. 사진과 자유문 리뷰를
추천 점수에 다시 넣는 것도 현재 증거로는 정당화되지 않는다.

다음 검증은 사용자 단위 A/B여야 한다.

- 대조군: 품질순 + 같은 중복 제거
- 실험군: 현재 8축 guarded policy
- 주 지표: 사용자별 카드 선호율, 10장 이후와 20장 이후를 별도 집계
- 보조 지표: 세션당 스와이프 수, 이탈률, 추천 다양성, 응답 지연
- 필수 로그: 정책 버전, 노출 순번, 카드 ID, 각 점수 항, 선호, 시각

관측 uplift가 약 0.5%p라면 일반적인 80% 검정력으로는 대략 arm당 15만 노출 규모가
필요하다. 초기에는 효과 크기보다 손상 여부와 사용자별 일관성을 먼저 본다.
