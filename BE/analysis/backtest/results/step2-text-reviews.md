## 가게 요약문 — 한 문장짜리 modality

카카오가 가게마다 붙여 놓은 `ai_title + ai_summary + tags + review_tags` 를 문장 하나로 이어 붙여 임베딩한 것이다(평균 189자). 가게당 벡터가 **1개**라 MaxSim 이 없고, 남는 자유도는 이력 위의 집계뿐이다.

- **풀 커버리지 2,203 / 2,216 = 99.4%.** 요약문이 없는 13곳(아이언케이스익스프레스, 청운반점, 더피자, 스토브키친, 컴포즈커피 테헤란아이파크점, 카페자스 역삼점, AAA유학수면캡슐카페, 커피스미스 본사점2…)은 유사도가 **NaN** 이고, Step 1 의 메뉴 NaN 규칙을 그대로 쓴다 — 이력 쪽이 NaN 이면 집계에서 빼고, 후보 쪽이 NaN 이면 그 사용자의 평균 점수(중립)로 채운다. 0 으로 채우면 '모른다' 가 '싫다' 로 번역된다.

## 리뷰 다중 벡터 — 어떤 12개를 고르나

가게마다 리뷰 **≤ 12개**를 집합으로 들고, 메뉴와 **같은 코드**(`analysis.content.menus.similarity_matrix`)로 MaxSim 을 잰다. 리뷰 쪽에서 새로 정하는 것은 '어떤 12개를 고르나' 뿐이고, 그것이 이 절의 질문이다.

```
MaxSim(A→B) = mean_{a∈A} max_{b∈B} a·b      (리뷰는 가중치 전부 1)
sim(A, B)   = (MaxSim(A→B) + MaxSim(B→A)) / 2
```

- **누수 규칙.** 평가 사용자 227명이 쓴 리뷰 **2,674건**을 가게 표현에서 전부 뺐다(임베딩된 리뷰 기준). 이력 구간이든 미래 구간이든 상관없다 — 평가 사용자의 문장이 가게 표현에 남으면 그 사람의 취향으로 그 사람의 정답을 맞히게 된다. `tests/test_review_content.py` 가 선택된 review_id 에 평가 사용자의 것이 하나도 없음을 검증한다.
- **쓸 수 있는 리뷰의 분포** (후보 풀 2,216곳): 0건 **102곳**, 1~11건 **1,394곳**, 12건 이상 **720곳**. 가게당 평균 8.9건 · 중앙값 7건 · 최대 39건. **0건인 102곳은 유사도가 NaN** 이고 메뉴와 같은 중립 처리를 받는다. '≤ 12개' 라고 썼지만 실제로 12개를 채우는 가게는 32% 뿐이다 — 이 modality 의 해상도는 대부분의 가게에서 리뷰 몇 건이다.

**대조군을 둘 둔다.** `single` 은 가게 = 리뷰 12개의 평균 벡터 1개, 사용자 = 방문 가게 평균 1개, 코사인이다 — 다중 벡터의 이득이 '집합' 때문인지 본다. `review_null_*` 는 **개수 구조는 그대로 두고 벡터만 난수로 바꾼 것**이다. MaxSim 의 `max_{b∈B}` 는 B 가 클수록 커지므로 리뷰가 12개인 가게는 내용과 무관하게 유사도가 높게 나오고, 리뷰 수는 곧 `popularity` 다 — 즉 리뷰 MaxSim 점수의 일부는 **인기의 다른 이름**일 수 있다. 난수 대조군의 성능이 그 몫이다. (쓴 리뷰 벡터 수와 log1p(리뷰 수)의 상관 **0.88**)

## 무엇을 쟀나

- **후보 풀 2,216곳** — 전체 2,795곳 중 카카오 리뷰 1+ 이고 사진 1+ (`swipe._build_pool` 과 같은 규칙). README 의 2,216 과 일치하고 `swipe.py` 주석의 2,045 는 옛 수치다.
- **평가 사용자 227명** — 후보 풀 안 리뷰 T ≥ 10. T 평균 18.4 · 중앙값 14 · 최대 91.
- **미래(정답) F = max(3, ceil(0.3·T))** — N 과 무관하게 고정. 사용자당 평균 5.9곳, 합 1,342곳.
- **이력 N** — 미래 직전의 최근 N 건(중첩). N 을 다 채운 사용자 수:

| N | 3 | 5 | 10 | 20 |
|---|---|---|---|---|
| 이력 N 을 다 채운 사용자 | 227 / 227 | 227 / 227 | 108 / 227 | 31 / 227 |
| 모델에 실제로 들어간 신호(평균) | 3.0 | 5.0 | 8.8 | 11.2 |
| 같은 것, N 을 다 채운 사용자만 | 3.0 | 5.0 | 10.0 | 20.0 |
| (참고) `like_dislike` 해석이었다면 | 2.3 | 4.0 | 7.0 | 8.8 |

이력 해석은 **`visit`(방문 = 관심)** 이다 — 이력의 모든 방문이 가중 1 의 양성 신호이고 dislike 가 없다(PLAN 5절 Step 1.5 결정 1번). 별점을 보지 않으므로 버리는 신호가 없고, N 을 다 채운 사용자에게는 신호 수가 곧 N 이다. N 을 못 채운 사용자 때문에 전체 평균은 N 보다 작다.

## 구성요소 블렌드

PLAN 3절: *"온라인 학습은 1,024차원 벡터 위에서 하지 않는다. 사용자별로 학습하는 것은 **구성요소 점수의 가중치 몇 개**뿐이다."* 그 가중치가 오프라인에서라도 학습되는지, 어떤 구성요소가 실제로 기여하는지를 여기서 잰다.

```
score(i) = z_pop(i) + Σ_m λ_m · z_m(i)
```

- z 는 **그 사용자의 후보**(이미 간 가게를 뺀 나머지) 안에서 낸다. 눈금이 modality 마다 다르므로(코사인 0.55 대 공방문 0.02) 정규화 없이 더하면 큰 눈금 하나가 전부를 결정한다.
- **NaN 은 z 정규화 뒤 0** 이다 — 그 사용자 후보의 평균, 즉 '모른다'.
- `popularity` 의 가중치는 1 로 고정한다. λ 는 '인기 위에 취향을 얼마나 얹을까' 이고, 그래야 `hybrid_pop_*` 와 같은 눈금으로 읽힌다.

**(a) 격자 탐욕 전진 선택** — λ ∈ {0, 0.25, 0.5, 1, 2}, 학습 폴드의 NDCG@20 가 가장 많이 오르는 (구성요소, λ) 를 하나씩 붙이고 더 오르지 않으면 멈춘다.

**(b) 쌍대 로지스틱 (BPR)** — 학습 폴드의 사용자마다 양성(미래 방문) 하나당 씨앗 고정 무작위 음성 20곳을 뽑아 σ(w·(z⁺−z⁻)) 를 최대화한다. 절편 없음, L2 계수는 학습 폴드 안에서 {0.001, 0.01, 0.1, 1, 10} 중에 고른다. 순위는 w 를 상수배해도 같으므로 표에는 **w_pop 으로 나눈 λ** 를 적는다.

## 사례 — 리뷰가 무엇을 맞췄나

리뷰 **MaxSim(`longest12`)** 유사도로 본 예시 가게 5곳의 이웃 5곳씩. **Step 1 이 쓴 것과 같은 가게**다 — 같은 가게를 두 modality 로 나란히 보려는 것이다.

## 배운 것 / 증명하지 못한 것

### 배운 것

- **modality 마다 이기는 지표가 다르다는 Step 1.5 의 관찰이 요약문에서도 반복된다.** `text_lse01` 는 auc_pm 에서 `popularity` 를 +0.0346 앞서지만 전체 AUC 에서는 -0.1014 뒤진다. 인기를 통제하면 콘텐츠가 이기고, 통제하지 않으면 인기가 이긴다.
- **어떤 리뷰 12개를 고르나 vs 어떻게 접나.** 선택 변종 사이의 NDCG@20 폭은 0.0027, 집계 사이의 폭은 0.0022 다 (`longest12` 0.0109, `random12` 0.0110, `recent12` 0.0083). 둘 다 이 정도로는 중요하지 않다 — 어느 쪽으로 바꿔도 폭이 비슷하다.
- **리뷰 MaxSim 의 AUC 는 '리뷰가 몇 개냐' 다.** 벡터를 난수로 바꾸고 개수 구조만 남긴 대조군이 AUC 0.6171 를 낸다 — **진짜 벡터보다도 높다**(대조군 0.6171 > 최고 MaxSim 0.6153) — 리뷰 MaxSim 의 AUC 는 내용이 아니라 개수로 설명된다. MaxSim 의 `max_{b∈B}` 가 B 의 크기에 단조증가하는데 리뷰 수가 곧 인기이기 때문이다(쓴 벡터 수와 log1p(리뷰 수)의 상관 0.88, `popularity` 의 AUC 는 0.6756). **인기를 통제하면 이야기가 뒤집힌다**: 같은 대조군의 auc_pm 은 0.4820(무작위 이하)이고 진짜 벡터는 0.5420 다 — 리뷰 내용에 신호가 있다는 증거는 AUC 가 아니라 auc_pm 쪽에 있다.
- **PLAN 원칙 1번('가게를 하나의 벡터로 평균내지 않는다')이 리뷰에서는 뒤집혔다.** 단일 벡터 대조군이 MaxSim 을 모든 지표에서 이긴다 — NDCG@20 0.0168 vs 0.0110, AUC 0.6477 vs 0.6153, auc_pm 0.5457 vs 0.5420. 리뷰 12개의 평균 벡터는 **개수 편향이 없고**(정규화된 벡터 1개라 집합 크기가 점수에 안 들어간다) 잡음이 평균으로 지워진다. late interaction 이 이기려면 집합 안에서 **서로 다른 면**을 말하는 원소들이어야 하는데, 한 가게의 리뷰 12개는 대체로 같은 말을 다르게 한 것이다. 메뉴에서는 MaxSim 이 나았다는 Step 1 결과와 반대이고, 그 차이가 바로 '집합이 다양한가' 다.

- **다중비교 보정을 하지 않았다.** 이 문서에는 모델 × N × 지표로 수백 개의 칸이 있고, 그 중 몇 칸이 우연히 유의할 수 있다. 개별 칸이 아니라 **여러 칸이 같은 방향으로 몰려 있는지**만 읽는다.
- **블렌드의 가중치는 사용자별이 아니라 전역이다.** PLAN 3절이 말한 '사용자별 가중치' 는 여기서 재지 않았다 — 폴드 안의 모든 사용자가 같은 λ 를 쓴다. 사용자별 학습은 Step 4 의 일이고, 이 문서는 그 전제(구성요소 몇 개로 충분한가)만 확인한다.
- 리뷰 텍스트는 **가게 표현**으로만 썼다. 평가 사용자 본인의 리뷰 원문은 어떤 모델의 입력도 아니다(PLAN 1절). 제품이 추천 시점에 아는 것은 (가게, 방문) 뿐이라는 계약 그대로다.
- 정답이 카카오 리뷰에서 나왔다는 표본틀 편향은 그대로다. 리뷰 modality 는 **그 편향과 같은 재료**로 만들어졌다 — 리뷰가 많은 가게가 리뷰 벡터도 많고 정답이 될 확률도 높다. `auc_pm` 이 그 일부를 통제할 뿐이다.
- 후보 풀 2,216곳 중 **102곳은 쓸 수 있는 리뷰가 0건**이고 1,394곳은 12건을 못 채운다. 이 가게들에 대한 리뷰 modality 의 성능은 이 실험이 재지 못한다.

## 읽는 법과 주의

- **CI 가 0 을 포함하면 우위 미확정이다.** 작은 양수를 근거로 삼지 않는다(PLAN 1절).
- 이력 해석은 **`visit`**(방문 = 관심)다 — PLAN 5절 Step 1.5 결정 1번의 기본값. `--history like_dislike` 로 옛 해석을 재현할 수 있다.
- 기준이 **둘**이다. '과제 P' 표의 CI 는 `popularity` 대비, '결선' 표의 CI 는 막대 `hybrid_pop_cf_item_sum_cv_ndcg20` 대비다. 같은 숫자를 두 잣대로 본 것이지 다른 실험이 아니다.
- 가게 표현에 쓴 리뷰에서 평가 사용자 227명의 리뷰 2,674건을 **전부** 뺐다. 제외는 `ReviewSpace.build` 한 곳에서만 일어나고 테스트가 그것을 검증한다.
- 막대(`hybrid_pop_cf_item_sum_cv_ndcg20`)는 이 실행에서 **다시 계산했다** — 같은 seed·같은 분할이므로 step1_5-visit-cf 의 값과 같아야 한다. 다르면 둘 중 하나가 깨진 것이다.
- 막대의 이름에 `_cv_ndcg20` 이 붙는 것은 λ 를 폴드 밖에서 고른 모델이기 때문이다. `analysis.backtest.run --ref` 로 같은 비교를 하려면 λ 가 박힌 이름(`hybrid_pop_cf_item_sum_l0.5`)을 써야 한다 — `hybrid_pop_cf_item_sum` 은 λ 없이는 이름 규칙에 걸리지 않아 모델로 풀리지 않는다.
- 하이브리드와 블렌드의 z 정규화는 **그 사용자의 후보**(이미 간 가게를 뺀 나머지) 안에서 한다. 미래(정답) 정보는 들어가지 않는다.
- 블렌드의 가중치는 **폴드 밖에서** 학습한다(`blend.outer_cv_blend`). 사용자마다 자기가 학습에 참여하지 않은 모델의 점수가 남으므로 다른 모델과 그대로 paired bootstrap 에 넣을 수 있다.
- BLAS 스레드 수에 따라 부동소수 합의 순서가 달라져 마지막 자리가 흔들릴 수 있다. 이 실행은 임베딩 작업과 코어를 나눠 쓰느라 1스레드로 돌렸다.
