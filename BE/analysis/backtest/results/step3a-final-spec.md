## 무엇을 쟀나

- **후보 풀 2,216곳** — 전체 2,795곳 중 카카오 리뷰 1+ 이고 사진 1+ (`swipe._build_pool` 과 같은 규칙). README 의 2,216 과 일치하고 `swipe.py` 주석의 2,045 는 옛 수치다.
- **평가 사용자 227명** — 후보 풀 안 리뷰 T ≥ 10. T 평균 18.4 · 중앙값 14 · 최대 91.
- **미래(정답) F = max(3, ceil(0.3·T))** — N 과 무관하게 고정. 사용자당 평균 5.9곳, 합 1,342곳.
- **이력 N** — 미래 직전의 최근 N 건(중첩). N 을 다 채운 사용자 수:

| N | 3 | 5 | 10 | 20 |

| 이력 N 을 다 채운 사용자 | 227 / 227 | 227 / 227 | 108 / 227 | 31 / 227 |
| 모델에 실제로 들어간 신호(평균) | 3.0 | 5.0 | 8.8 | 11.2 |
| 같은 것, N 을 다 채운 사용자만 | 3.0 | 5.0 | 10.0 | 20.0 |

이력 해석은 **`visit`(방문 = 관심)** 이다 — 이력의 모든 방문이 가중 1 의 양성 신호이고 dislike 가 없다(PLAN 5절 Step 1.5 결정 1번). 별점을 보지 않으므로 버리는 신호가 없고, N 을 다 채운 사용자에게는 신호 수가 곧 N 이다. N 을 못 채운 사용자 때문에 전체 평균은 N 보다 작다.

## 서빙 사양 — 서버가 실을 것

채택: **(d) `blend_d_no_review_quality`** — 성분 `popularity`, `quality`, `cf`, `menu`, `text`.

PLAN 6절이 요구한 *"w 의 사전값은 오프라인 블렌드의 CV 가중치"* 를 채운다. N 별 폴드 평균 λ 를 다시 N 으로 평균해 소수 둘째 자리에서 반올림한 것이다.

| N | λ(quality) | λ(cf) | λ(menu) | λ(text) |
|---|---|---|---|---|
| 3 | 0.050 | 0.395 | 0.201 | 0.379 |
| 5 | 0.050 | 0.473 | 0.238 | 0.460 |
| 10 | 0.059 | 0.461 | 0.267 | 0.379 |
| 20 | 0.059 | 0.512 | 0.275 | 0.402 |
| **N 평균 (반올림)** | **0.05** | **0.46** | **0.25** | **0.40** |

```json
{
  "components": [
    "popularity",
    "quality",
    "cf",
    "menu",
    "text"
  ],
  "weights": {
    "popularity": 1.0,
    "quality": 0.05,
    "cf": 0.46,
    "menu": 0.25,
    "text": 0.4
  },
  "prior_sd": 0.5,
  "source": "step3a",
  "n_users": 227,
  "history": "visit"
}
```

`analysis/backtest/results/serving_prior.json` 에 그대로 적혀 있다. `prior_sd` 0.5 는 **선택이지 추정값이 아니다** — 온라인 쌍대 갱신(PLAN 6절)이 사용자마다 사전값에서 벗어날 여지를 남기려고 폴드 간 표준편차보다 넉넉하게 뒀다.

**N 평균의 뜻을 오해하지 말 것.** N=10·20 을 다 채운 사용자는 108명·31명뿐이고 그 사람들은 N=3·5 에도 들어 있다. 네 N 의 평균은 '이력 길이에 무관한 값' 이지 '독립 표본 4개의 평균' 이 아니다.

**서버가 알아야 할 것.**

| 성분 | 점수 계산 | 필요한 산출물 |
|---|---|---|
| `popularity` | `log1p(review_count)` 의 후보 내 z | 없음(가게 표에 있다) |
| `quality` | 베이지안 평균 평점(C=10)의 z | 없음 |
| `cf` | `Σ_{h∈L} cooc_cos(h, i)` | `cooc.npz` |
| `menu` | `max_{h∈L} MaxSim_menu(h, i)` | `sim_menu.npy` |
| `text` | `logsumexp_{h∈L}(τ=0.1) cos_text(h, i)` | `sim_text.npy` |

- 성분 z 는 **그 사용자의 후보 안에서** 낸다(이미 간 가게 제외). NaN 은 z 뒤 0.
- `text` 의 집계는 **`lse01`(logsumexp τ=0.1)** 이다 — PLAN 6절이 적어 둔 `max` 가 아니다. Step 2 스윕에서 요약문은 `lse01` 이 이겼다.
- **`review` 는 점수에서 빠지지만 산출물은 남는다.** PLAN 7절 결정 2번의 추천 이유("좋아요한 ○○의 리뷰와 닮았어요: '…'")가 리뷰 쌍을 필요로 하므로 `sim_review.npy` 는 계속 만든다. 점수에 안 쓴다는 것뿐이다.

## 배운 것 / 증명하지 못한 것

### 배운 것

1. **집합형 대조군은 modality 마다 답이 다르다.** 리뷰에서는 난수가 이겼고 메뉴에서는 지지 않았다. 두 결과를 가른 것은 개수 ↔ 인기 상관이다(리뷰 0.88 vs 메뉴 0.196). 사진(Step 3b)에서도 **먼저 이 상관을 보고** 대조군을 읽어야 한다.
2. **성분 상관이 ablation 결과를 설명한다.** Step 2 에서 `review` 는 가장 큰 λ (0.47~0.68)를 받고도 빼도 지표가 안 나빠졌다. N=5 상관 행렬에서 그 이유가 보인다 — 아래 '성분 상관' 절의 표를 볼 것.
3. **`quality` 는 과제 P 를 해치지 않으면서 R 을 조금 올린다.** (a) vs (b): 과제 R AUC 차이(품질 뺀 쪽 − 넣은 쪽) N=3 -0.0065 [-0.0143, +0.0001], N=5 **-0.0149** [-0.0271, -0.0037], N=10 **-0.0066** [-0.0118, -0.0018], N=20 **-0.0099** [-0.0205, -0.0019] / (c) vs (d): 과제 R AUC 차이(품질 뺀 쪽 − 넣은 쪽) N=3 -0.0035 [-0.0090, +0.0010], N=5 **-0.0068** [-0.0151, -0.0004], N=10 +0.0000 [-0.0098, +0.0115], N=20 +0.0017 [-0.0109, +0.0141]. 과제 P 에서 `quality` 단독은 AUC 0.50(무작위)인데도 블렌드가 λ 를 0 으로 보내지 않았다 — 작지만(0.03~0.10) 전 폴드에서 양수다. PLAN 7절 6번의 질문('넣을지, λ 가 0 이 되는지')에 대한 답은 **넣는다** 이다.
4. **`review` 는 인기의 다른 이름이었다.** 사용자 내 스피어만 ρ(`review`, `popularity`) = +0.673. Step 2 에서 가장 큰 λ 를 받고도 ablation 에서 죽은 것이 이것으로 설명된다 — 블렌드가 `review` 에 준 가중치의 상당 부분은 `popularity` 를 한 번 더 더한 것이었다.

### 증명하지 못한 것

- **다중비교 보정을 하지 않았다.** 이 실행에는 변종 5개 × 지표 4개 × N 4개의 CI 가 있고, 제거 시험이 5개 더 있다. 개별 칸의 95% CI 를 그대로 읽으면 우연히 유의한 칸이 몇 개는 나온다.
- **성분 선택은 테스트 사용자 위에서 이뤄졌다.** λ 는 바깥 5-fold 로 폴드 밖에서 학습했지만, '어떤 변종을 채택할까' 는 전체 227명의 지표를 보고 정했다. 폭이 작은 차이는 이 선택 편향 안에 있다.
- **효과의 크기는 여전히 AUC 0.01 수준이다.** PLAN 4절의 기준(CI 가 0 을 넘긴 구성만 서버에 켠다)은 충족해도, 그것이 사용자가 느끼는 차이라는 근거는 아직 없다. 온라인 팀-드래프트 인터리빙(PLAN 6절)이 남은 시험이다.
- **과제 R 은 표본이 작다.** 양쪽 클래스가 다 있는 사용자만 세므로 172명이고, CI 가 넓다.
- **`quality` 를 넣어도 R 이 '고쳐지지는' 않는다.** 블렌드의 R AUC 는 0.5154 인데 `quality` **단독**은 0.7037 다. λ 가 0.05 수준이라 순위를 거의 안 바꾸기 때문이다. 만족을 정말 지키려면 R 을 목적함수에 넣거나(지금은 P 만 학습한다) 별도의 가드가 필요하다.
- **성분 집합의 선택은 지표가 갈라 주지 않았다.** 다섯 변종이 전부 막대를 넘고 서로 간의 차이는 대부분 CI 안이다. 결정을 실제로 이끈 것은 상관 행렬과 '없어도 지지 않는다' 이지 '이것이 더 낫다' 가 아니다.

## 읽는 법과 주의

- 과제 P 의 기준은 `popularity`, 과제 R 은 `quality` 다(PLAN 5절 1번). 막대 대비 CI 는 '블렌드 변종' 절의 표에 따로 있다.
- 블렌드 변종은 전부 **바깥 5-fold** 다 — 폴드 f 를 뺀 사용자로 λ 를 학습하고 폴드 f 만 평가한다. 사용자마다 자기가 학습에 참여하지 않은 모델의 점수가 남으므로 다른 모델과 그대로 paired bootstrap 에 넣을 수 있다.
- 성분 상관은 이력 N=5 한 곳에서만 쟀다. N 이 커지면 이력 위의 집계가 더 매끄러워져 상관이 조금 올라갈 수 있다 — 재지 않았다.
- 난수 대조군의 벡터는 seed 고정이다. 다른 seed 로 다시 뽑으면 숫자가 조금 달라지지만(난수 벡터 한 벌만 썼다) 대조군의 뜻은 개수 구조에 있으므로 결론이 바뀌지는 않는다 — 그래도 **난수 벡터 한 벌로 잰 값**이라는 것은 한계다.
- BLAS 스레드 수에 따라 부동소수 합의 순서가 달라져 마지막 자리가 흔들릴 수 있다. 이 실행은 다른 작업과 코어를 나눠 쓰느라 1스레드로 돌렸다.
