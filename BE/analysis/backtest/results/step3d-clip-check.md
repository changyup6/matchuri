# Step 3d — 온라인에서 켠 z 자르기의 오프라인 확인 (step3d-clip-check)

생성 2026-09-09T17:01:39+09:00 · seed `20260909` · 커밋 `70956fa-dirty`

실서버에서 취향 가중치가 폭주했다 — 사용자 하나의 `w_cf` 가 0.46 → **−63.63**. 원인 둘 다 z 의 문제였고(쌍의 상대쪽 가게가 이력에 남아 자기 자신과의 유사도로 z 를 부풀린 것, 희소한 `cf` 의 z 가 ±40 을 넘은 것), 서버는 이제 z 를 [−3, 3] 으로 자른다.
그런데 서버의 사전 가중치는 **자르지 않은 z 위에서** 학습된 λ 다. 자른 눈금 위에서도 그 λ 가 맞는 값인지가 이 문서의 질문이다.

```bash
~/venvs/recsys/bin/python -m analysis.backtest.step3d \
    --N 3,5,10,20 --history visit --clip 3 \
    --out step3d-clip-check
```

## 한눈에

- **λ 는 사실상 그대로다** — 지금 실린 사전값에서 가장 많이 움직인 것이 `text` 의 +0.03 이고 임계 0.05 아래다. 자르기는 **어떤 성분을 얼마나 믿을지**를 바꾸지 않았다.
- **대신 상위 구간이 눌린다** — `hit@10` N=3 이 -0.0396 [-0.0837, +0.0000] 로 가장 크게 움직였고, 임계 0.005 을 넘은 칸이 6개다: hit@10 N=3, hit@10 N=5, hit@10 N=10, hit@10 N=20, ndcg@20 N=3, ndcg@20 N=20. `hit@10`·`ndcg@20` 이 흔들리는 것은 우연이 아니다 — 잘리는 값이 곧 상위 카드다(N=5 에서 `cf` 의 2.7%, 자르기 전 최대 +41.9).
- **사전값을 자른 눈금 위에서 다시 학습한 값으로 적는다**(`source: step3d-clip`) — 서버가 자른 z 로 점수를 내는 이상 사전값도 같은 눈금에서 나온 것이어야 한다.
- N=5 기준 자르기 전 → 후: `auc` 0.6952 → 0.6937 · `auc_pm` 0.5864 → 0.5844 · `hit@10` 0.1366 → 0.1057 · `ndcg@20` 0.0273 → 0.0244

## 무엇을 쟀나

- 성분 **`popularity`, `quality`, `cf`, `menu`, `text`** — Step 3a 가 고른 서빙 사양(변종 (d)) 그대로다.
- 학습 **쌍대 로지스틱 + 바깥 5-fold**, 이력 해석 `visit`, 평가 사용자 227명, 후보 풀 2,216곳.

## 판정

규칙에 걸렸다(지표 조건). `results/serving_prior.json` 을 자른 눈금 위에서 학습한 λ 로 다시 적고 서빙 산출물을 다시 만든다:

| | `popularity` | `quality` | `cf` | `menu` | `text` |
|---|---|---|---|---|---|
| step3c (자르지 않은 z) | 1.00 | 0.05 | 0.46 | 0.25 | 0.40 |
| step3d-clip (자른 z) | 1.00 | 0.04 | 0.45 | 0.24 | 0.43 |

```bash
~/venvs/recsys/bin/python -m analysis.build_serving --only prior,manifest
```

**바꾼 이유는 λ 가 아니라 눈금이다.** λ 는 소수 둘째 자리에서 거의 같지만, 이 값이 살아갈 세계는 이제 자른 z 다. 사전값과 서빙 점수가 서로 다른 눈금에서 나오면 '사전값에서 얼마나 벗어났나' 라는 관리자 화면의 질문 자체가 어긋난다.

**그리고 이 표가 자르기의 값이 아니라 대가를 말한다는 것을 적어 둔다.** 자르기는 오프라인 상위 구간을 조금 잃는다(`hit@10` 네 N 에서 −0.013~−0.040, CI 로 진 칸은 `ndcg@20` N=20 하나). 그 대가로 얻는 것은 **온라인에서 한 사람의 가중치가 카드 한 장에 뒤집히지 않는 것**이고, 실측이 −63.63 이었다. 227명 평균의 상위 10장과 한 사람의 모델이 살아남는 것 중 후자를 고른 것이고, 이것은 측정이 아니라 **선택**이다.

## 주의

1. **자르기 폭 3σ 는 스윕한 값이 아니다.** 온라인 한 걸음의 크기를 `v·Δz` 로 묶으려고 고른 값이다. 이 표가 보여 주는 대로 폭을 넓히면(5σ·6σ) 오프라인 상위 구간을 덜 잃으면서도 폭주는 막을 수 있다 — **폭을 스윕한 적은 없고**, 그것은 다음 실험거리다. 지금 3 을 택한 이유는 '3σ 밖은 어차피 순위를 못 가르는 자리' 라는 통념뿐이고, 이 문서가 그 통념의 대가를 숫자로 남긴다.
2. **오프라인은 dislike 를 모른다.** 이력 해석이 `visit` 라 `neg` 성분이 없고, 실서버 폭주를 만든 `like A → dislike A → like B` 같은 순서도 없다. 자르기와 leave-one-out 이 그 경로에서 무엇을 하는지는 서버 테스트가 잰다(`server/tests/test_taste.py`, `server/tests/test_replay.py`).
3. **`hit@10` 은 이 표에서 가장 거친 지표다.** 사용자 227명의 0/1 이라 CI 가 ±0.04 로 넓고, N=5 의 −0.0308 도 CI 가 0 을 넘는다. '상위가 눌린다' 는 방향은 네 N 에서 모두 같지만 크기는 이 표로 정할 수 없다.
4. **사전값을 바꾸면 사용자별 학습의 출발점이 바뀐다.** 이미 스와이프한 사람의 모델은 재생으로 다시 만들어지므로(`preferences.jsonl`) 새 사전값에서 다시 출발한다 — 배포 시점에 관리자 화면의 가중치가 조금 달라 보이는 것이 정상이다.
