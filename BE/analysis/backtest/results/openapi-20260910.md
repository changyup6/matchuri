# OpenAPI 타입 — 실서버 확인 (2026-09-10)

프론트가 `/openapi.json` 한 파일로 타입을 만들 수 있게 모든 클라이언트 엔드포인트에
응답 모델을 붙였다. 확인은 임시 `MATCHURI_STATE` · 포트 8015 · interleave 로 띄운
실서버에서 `GET /openapi.json` 을 받아서 했다.

```bash
cd server && MATCHURI_STATE=$(mktemp -d) uvicorn main:app --port 8015
curl -s http://127.0.0.1:8015/openapi.json | jq .        # /docs 도 같은 값을 그린다
npx openapi-typescript http://127.0.0.1:8015/openapi.json -o api.d.ts   # 프론트 쪽 한 줄
```

(이 EC2 는 오프라인이라 `npx` 를 실제로 돌리지는 못했다 — 아래 표가 그 도구가 읽는
바로 그 값이다.)

## 허용 값이 스키마에 있다

```json
FilterIn.cat.items   {"type": "string", "enum": ["한식", "카페", "일식", "술집", "양식", "중식", "간식", "분식", "기타"], "examples": ["일식"]}
FilterIn.tag.items   {"type": "string", "enum": ["가성비", "친절", "양많은", "혼밥", "점심식사", "야식", "단체모임", "분위기", "데이트", "술한잔", "조용한", "주차"], "examples": ["혼밥"]}
Log.prefer           {"type": "string", "enum": ["like", "dislike"]}
Store.category_group {"type": "string", "enum": ["한식", "카페", "일식", "술집", "양식", "중식", "간식", "분식", "기타"]}
CardOut.policy       [{"type": "string", "enum": ["legacy", "taste"]}, {"type": "null"}]
```

업종·태그는 `app/filters.py` 의 어휘를 그대로 싣는다(`CAT_CHOICES` · `TAGS` 의 키). 타입은
`str` + 스키마 `enum` 이고 `Literal` 이 아니다 — 이유는 둘이다. ① 옛 값을 보낸 클라이언트가
pydantic 의 영어 422 대신 `filters.validate` 의 한국어 메시지("cat '초밥' 은 없는 값입니다.
허용: …")를 받아야 하고, ② 어휘가 줄어든 뒤 파일에 남아 있던 옛 필터를 응답에 실을 때
`Literal` 이면 **500** 이 된다. 코드 생성기는 `enum` 만으로 유니온 타입을 만든다.
`policy` 는 서버 상수(`recsys/policy.py`)라서 `Literal` 이다.

`prefer` 도 같은 이유로 `str` + `enum` 이다 — 잘못된 값의 응답은 예전부터 **400**
(`{"detail": "prefer must be 'like' or 'dislike'"}`)이고, `Literal` 로 바꾸면 그게 422 로
변한다(기존 계약·테스트가 400 을 잠그고 있다).

## 응답 모양이 바뀐 곳 — 한 군데

**미등록 id 에 설정을 저장한 응답**이다. `PUT /users/{id}/location` 을 발급받지 않은 id 로
부르면 예전에는 `filter` 키가 **아예 없는** 레코드가 돌아왔다(그 반대도 마찬가지). `GET
/users/{id}` 는 `users._public` 을 지나므로 늘 두 키가 있었는데 PUT 경로만 그러지 않았다 —
같은 엔드포인트가 사용자에 따라 다른 모양을 주던 것이고, 타입을 붙이자 응답 검증이 바로
잡아냈다. 이제 `_ensure` 가 두 키를 `null` 로 만들어 두고 세 설정 API 모두 `_public` 을
통과한다(키가 늘어나는 방향이라 기존 클라이언트에는 무해하다). 그 밖의 응답은 필드·순서·값이
모두 그대로다 — 190개 테스트가 JSON 모양을 잠그고 있고 손대지 않았다.
